Layout rules

Product: 12 columns on desktop, 8 on tablet, 4 on mobile. Page padding: 32 / 24 / 16px. Gutters: 24 / 24 / 16px.

Website: centered content, maximum 1280px. Section spacing: 96 / 64 / 48px. Side padding: 32 / 24 / 16px.

Desktop navigation: 240px sidebar. Tablet and mobile: drawer navigation. Dense tables scroll within their own region; pages must not overflow horizontally.

Shape & elevation

6px small items · 8px controls · 12px cards · 16px panels · full radius for badges. Use borders for structure, subtle shadows for elevated cards, and stronger shadows for overlays.

05 / Owner workspace patterns

Clear company boundaries.

Company switcher

Always display the active company beside navigation. Switching opens a separate company context and updates all records, filters, counts, and actions. Never combine company data by default.

Permissions & ownership

Owners have full company access and equal authority. Other roles use explicit permissions and scopes. Hide inaccessible navigation; explain restricted actions where context is useful. Enforce access on the server.

Dashboard & profiles

Show summaries only for enabled modules. Cards link to their source records. Employee profiles group personal, employment, HR, compensation, documents, work, access, and history information.

Audit & destructive actions

Record actor, company, action, target, time, and outcome. Owner removal must name the affected person and company. Keep the last-owner protection established in the brief.

Required component states

Design default, hover, focus, pressed, disabled, loading, empty, error, success, and restricted states as applicable. Empty states explain the next action; errors preserve entered information; loading regions announce updates.

06 / Working with the system

Built to evolve.

Use primitive → semantic → component tokens. Add new tokens only for a reusable purpose. Keep names about meaning, such as text-secondary, rather than appearance, such as gray-500.

Accessibility baseline

Target WCAG 2.2 AA: 4.5:1 for normal text, 3:1 for large text and essential UI boundaries. Use border-strong on inputs; border-subtle is decorative. Provide visible keyboard focus, associated labels, logical reading order, and text alternatives. Never rely on color alone.

Interactive touch targets are at least 44 × 44px. Compact 32px controls are desktop-only and need appropriate target spacing. Support 200% text zoom and reflow at 320px. Respect reduced-motion preferences.

Owner workspace component scale

The owner UI uses 14px reading text, 13px labels, 12px supporting copy, 16px panel titles and 32px key metrics. Card padding is 20px and section gaps are 16px. Desktop controls are 36px high; mobile controls retain 44px touch targets. Shared ui-* tokens keep these decisions consistent across screens.

Iconography · Tabler

Use Tabler outline icons throughout the product. Active sidebar items use official filled variants where available. Sizes: 16px in buttons, 18px in navigation, 20px in content; stroke 1.75px. Decorative icons are hidden from assistive technology and icon-only controls need accessible labels. Assets and MIT licensing are stored locally.

Files & adoption

tokens.json is the token inventory. tokens.css contains semantic variables, responsive type classes, and starter controls. Apply type-product or type-website to a container, then use t-heading-1, t-body, and related classes.

This is a foundation reference with sample components. Production widgets such as dialogs, menus, tabs, and data grids require complete keyboard behavior and application integration.
